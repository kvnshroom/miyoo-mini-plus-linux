# Miyoo Mini Plus panel

Recorded 2026-10-11 by booting the device's own SPI dump in QEMU
(`miyoomini-plus`, trace `dsi_dcs_panel_payload`). The running config section
was read (read-only) from the real device.

## Controller

The first command is `B9 F1 12 83` (SETEXTC), the unlock sequence of the
**Sitronix ST7703**. Mainline Linux drives this controller with
`drivers/gpu/drm/panel/panel-sitronix-st7703.c`, which takes one init function
per panel variant, so the Plus panel can become one more variant there.

## Timing (vendor U-Boot)

U-Boot prints `_BootDispCtrl ... H(98 20 22 640) V(17 5 13 480) Fps:60`.
The format in SigmaStar `cmd_bootlogo.c` is `H(hfp hsw hbp hact) V(vfp vsw vbp vact)`.

| | active | front porch | sync | back porch | total |
|---|---|---|---|---|---|
| horizontal | 640 | 98 | 20 | 22 | 780 |
| vertical | 480 | 17 | 5 | 13 | 515 |

780 × 515 × 60 Hz = 24.102 MHz pixel clock. `PnlLink:11` = MIPI DSI.

## Running config (read on the real device, 2026-10-11)

`cat /proc/mi_modules/mi_panel/mi_panel0` under Onion (vendor kernel) shows:

- **2 data lanes**, RGB888, `sync_pulse` mode (non-burst with sync pulses),
  `SyncCalibrate 1`.
- Same totals (780 × 515, 60 Hz), but the horizontal porches are split
  differently from U-Boot: **hfp 96, hsync 20, hbp 24** (U-Boot: 98/20/22).
  Vertical matches: vfp 17, vsync 5, vbp 13. The kernel values are the ones the
  panel runs with all day, so use them for the mainline mode.
- `InvHSync 1`, `InvVSync 1` → negative sync polarity.
- `DClk 26` (vendor clock setting, rounded up from 24.1 MHz).
- D-PHY timing: HsTrail 3, HsPrpr 2, HsZero 5, ClkHsPrpr 2, ClkHsExit 4,
  ClkTrail 4, ClkZero 10, ClkHsPost 10, DaHsExit 4, Lpx 16, TaGet 26,
  TaSure 22, TaGo 50.
- The vendor panel name `K101_IM2BVL` is a generic SDK placeholder.

## Reset and backlight (U-Boot `bootcmd`)

`gpio output 73 1; sleepms 50; gpio output 73 0; sleepms 150; gpio output 73 1`
→ GPIO 73 is very likely the panel reset (active low).
`gpio output 4 1` right before `bootm` → GPIO 4 is likely the backlight enable/PWM pad.
GPIO numbers are vendor U-Boot numbering, not yet mapped to mainline pad names.

## Init sequence (vendor U-Boot)

MainUI (`/customer/app/MainUI`, table at file offset 0x15e54e) sends the same
sequence again after boot, with `B4`, `B6`, `B8`, `BA`, `E0` (gamma) and `EA`
adjusted, most likely from the user's screen settings (brightness, contrast,
saturation, hue). The U-Boot values above are the baseline.
